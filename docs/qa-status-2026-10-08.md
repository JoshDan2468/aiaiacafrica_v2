- Paystack checkout, signed live webhook delivery, refunds, reconciliation, and payment completion.
- Event-pass email delivery and QR scanning on an actual device.
- Student private evidence upload, scanner availability, review, and approved payment.

  commercial/abstract decisions, manual payments, and campaign delivery.

Automated tests cover many of these behaviours using controlled dependencies, but do not prove
the deployed services and provider integrations work together.

## Test interpretation

The initial simultaneous UI test run produced timing failures. A single-worker rerun eliminated
all Admin failures and left only the Student selection assertion in the public frontend.
The initial backend command failed during production environment validation. Running with
NODE_ENV=test exposed environment-dependent expectations and CORS failures. The successful
isolated run used NODE_ENV=development and CLIENT_URL, PUBLIC_FRONTEND_URL, and ADMIN_FRONTEND_URL
set to http://localhost:5173 for that process only. No environment files were edited.

Recommended order: unblock local API configuration, correct legal destinations, resolve the
remaining frontend test, decide which enquiry-only workflows are required for launch, and then
exercise complete payment/email/Admin journeys in a controlled staging environment.
